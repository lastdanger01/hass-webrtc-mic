# Tapo 相機麥克風對講 —— 完整安裝步驟

這份文件是給「想在別人的 HA 上做出攝影機麥克風對講」用的。

---

## 0. 先確認條件符不符合

在開始之前，先確認對方的環境符合這三條。**任何一條不符都不會有聲音**，而且症狀都是「麥克風按鈕有了，但相機沒聲音」，很容易搞錯方向。

| 條件 | 怎麼確認 | 不符會怎樣 |
|---|---|---|
| **① 相機是 Tapo，且支援 backchannel** | 看型號。Tapo C200/C210/C220/C225/C310/C320/C500/C510 等支援 | 完全沒聲音 |
| **② HA 有 HTTPS 或 localhost** | 瀏覽器網址列是 `https://` 開頭 | 麥克風按鈕會被瀏覽器直接擋掉，連圖示都不出現 |
| **③ go2rtc 正常運作** | HA → 設定 → 附加元件 → go2rtc，狀態是「已啟動」 | 影像也不會出來 |

> **關鍵提醒**：Tapo 相機的「ONVIF 帳號」通常是唯讀的、沒有 AudioOutput，**用 ONVIF 做對講一定失敗**。必須走 Tapo 私有協定 `tapo://`。

---

## 1. 安裝 WebRTC Custom Integration

如果對方還沒有：

1. HA → 設定 → 附加元件 → 右上角「新增存放區」
2. 輸入 `https://github.com/AlexxIT/hassio_webrtc`
3. 下載後到「附加元件」分頁安裝 **WebRTC Custom Integration**
4. 這需要對方的 HA 有 **HACS**，沒有就先裝 HACS

確認整合版本，記下來（後面 patch 要對得上）：

```
HA 設定 → 附加元件 → WebRTC Custom Integration → 右上角三點 → 資訊
```

## 2. 設定 go2rtc（這是音訊能不能出去的關鍵）

### 2.1 算出 Tapo 密碼

Tapo 私有協定用的密碼是**相機雲端帳號的密碼**，不是 RTSP 帳密，也不是網頁後台密碼。

用這段算 SHA256 並轉大寫：

```bash
python3 -c "import hashlib; print(hashlib.sha256(input('Tapo 密碼: ').encode()).hexdigest().upper())"
```

輸入雲端帳號的登入密碼，會得到一串 64 碼的大寫 hex。

### 2.2 寫入 go2rtc.yaml

在 HA 主機上編輯 `/config/go2rtc.yaml`（HA OS 上是 `/mnt/data/supervisor/homeassistant/go2rtc.yaml`）：

```yaml
log:
    level: info
streams:
    tapo85:
        - tapo://admin:<你的SHA256>
    tapo44:
        - tapo://admin:<你的SHA256>@192.168.31.44
```

把 `<你的SHA256>` 換成自己算出來的那串 64 碼 hex，`192.168.31.85` 換成相機 IP。

**一台相機一條 stream，名字自己取**（下面都用 `tapo85` 當例子）。

> 密碼那欄如果是 `admin`，代表相機的帳號名；Tapo 預設就是 `admin`。

### 2.3 重啟 go2rtc

HA → 設定 → 附加元件 → go2rtc → ⋮ → 重新啟動

### 2.4 驗證 backchannel 通了

在 HA 主機上跑：

```bash
curl -s http://localhost:1984/api/streams | python3 -m json.tool
```

找到剛剛的 stream，確認 `producers` 裡有 `tapo://` 開頭的 url。

再確認有音訊通道（這行一定要看到 `sendonly`）：

```bash
curl -s http://localhost:1984/api/streams?src=tapo85 | python3 -m json.tool
```

 medias 裡應該有類似：

```
"audio, sendonly, PCMA/8000"
```

**如果沒有 `sendonly` 這行，後面全部白做** —— 代表相機沒開放 backchannel，回去檢查密碼或相機型號。

## 3. 套用麥克風對講的 JS 補丁

上游的 WebRTC 整合**原本沒有麥克風對講**，UI 連麥克風按鈕都沒有。下面這個補丁是新增這個功能。

### 3.1 備份

```bash
cd /config/custom_components/webrtc/www
cp video-rtc.js video-rtc.js.bak
cp webrtc-camera.js webrtc-camera.js.bak
```

（HA OS 上路徑是 `/mnt/data/supervisor/homeassistant/custom_components/webrtc/www`）

### 3.2 套用

把 `webrtc-mic-patch.tar.gz` 解開，裡面有：

```
安裝步驟.md
README.md
apply_patch.py           <- 套用工具 (不需要系統的 patch 指令)
video-rtc.js.patch
webrtc-camera.js.patch
video-rtc.js.orig
webrtc-camera.js.orig
```

**方法 A：用內附的 Python 工具（推薦，不依賴任何額外指令）**

```bash
mkdir -p /tmp/micpatch && cd /tmp/micpatch
tar xzf /路徑/webrtc-mic-patch.tar.gz

cd /config/custom_components/webrtc/www
python3 /tmp/micpatch/apply_patch.py \
    /tmp/micpatch/video-rtc.js.patch      video-rtc.js \
    /tmp/micpatch/webrtc-camera.js.patch  webrtc-camera.js
```

成功會顯示：

```
=== .../video-rtc.js.patch  ->  video-rtc.js
  [成功] 套用 4/4 個區塊
  [備份] video-rtc.js.bak
```

**方法 B：用系統的 `patch` 指令（如果有的話）**

```bash
cd /config/custom_components/webrtc/www
patch -p0 < /tmp/micpatch/video-rtc.js.patch
patch -p0 < /tmp/micpatch/webrtc-camera.js.patch
```

成功會顯示 `patching file video-rtc.js` 之類的訊息。

> **如果出現「command not found: patch」** → 用方法 A，HA 主機本來就有 Python，不需要安裝任何東西。

> **如果出現「hunk 找不到相符位置」**：代表對方的整合版本跟補丁的基準版本不同。**這種情況工具不會修改任何檔案**，對方的檔案是安全的。請把錯誤訊息回報給提供補丁的人，不要硬套。

### 3.3 清掉瀏覽器快取

改了 JS 檔但畫面沒變，是快取。兩個地方要清：

1. **HA 端**：HA → 設定 → 系統 → 儀表板 → 右上角「資源」→ 找到 `WebRTC Camera` → 刪除
2. **瀏覽器端**：瀏覽器按 `Ctrl+Shift+R`（或 `Cmd+Shift+R`）強制重新載入

> 補丁改過 `webrtc-camera.js` 裡 import 的版本號（`./video-rtc.js?v=1.9.11-local2`），這是為了繞過快取。不過保險起見兩個地方都清一次。

## 4. 設定 HA 的網址（很容易漏掉）

HA 的 8123 埠如果是 **HTTPS-only**，那 `internal_url` 必須寫 `https://`：

HA → 設定 → 系統 → 選擇「網址」對應的項目，確認：

- **內部 URL**：`https://192.168.31.20:8123`
- **外部 URL**：`https://你的網域:8123`

填錯的症狀是 HA log 出現：

```
HomeAssistantError: Unable to determine Home Assistant URL to send to device.
```

這會讓相機喇叭播歌功能整個壞掉（不只是對講）。

## 5. 建立相機的 media_player 實體（選用，但建議做）

這是「HA 端播放音樂到相機喇叭」用的，跟瀏覽器麥克風對講是**不同的機制**。但做了之後相機就能當喇叭播歌，實用性差很多。

在 `configuration.yaml` 加入：

```yaml
media_player:
  - platform: webrtc
    name: Tapo 85 對講喇叭
    stream: tapo85
    audio: pcma
```

`stream` 要跟第 2 步 go2rtc.yaml 裡的名字一致。`audio` 固定用 `pcma`。

多台相機就多加幾段，改 `name` 和 `stream`。

改完重啟 HA。

## 6. 儀表板卡片

### 6.1 YAML 模式

```yaml
type: custom:webrtc-camera
url: tapo85
name: 屋前主攝影機
mode: webrtc
media: video,audio,microphone
muted: false
ui: true
```

**`media` 一定要包含 `microphone`**，少了這三個字麥克風就不會啟用。

> **為什麼用 `url:` 而不是 `entity:`？**
>
> 上游整合對兩者的處理完全不同：`entity:` 必須填真正的 camera entity_id
> （例如 `camera.tapo_c200_mainstream`），填 go2rtc 的 stream 名稱會直接報
> `Can't get URL for tapo85`；而 `url:` 完全不驗證，直接當成 go2rtc 的 src 丟出去，
> **填 go2rtc stream 名稱或完整 RTSP 網址都可以**。
>
> 所以對講卡片請用 `url:`。

### 6.2 圖形模式

設定 → 儀表板 → 編輯 → 新增卡片 → 搜尋 `webrtc-camera`，然後：

| 欄位 | 值 |
|---|---|
| URL / stream | `tapo85` |
| Name | 自己取 |
| Mode | `webrtc` |
| Media | `video,audio,microphone` |
| Muted | `false` |
| UI | `true`（有 `ui` 才會顯示麥克風按鈕） |

## 7. 驗收

1. 重新載入儀表板頁面
2. 攝影機卡片**左上角應該出現紅色麥克風圖示**
3. 點一下 → 圖示變綠色
4. 對著相機講話 → 相機喇叭應該有聲音

### 沒聲音的排查順序

| 檢查 | 怎麼查 |
|---|---|
| go2rtc 有 `sendonly, PCMA/8000` 嗎 | 第 2.4 步的指令 |
| 瀏覽器拿到麥克風權限了嗎 | 網址列左邊的相機／麥克風圖示 |
| PCMA 編碼有被指定嗎 | F12 → Console 看有沒有 `setCodecPreferences` 相關錯誤 |
| 真的有在送音訊嗎 | F12 → Console 執行 `pc.getStats()`，看 outbound audio bytes 有沒有增加 |
| 是不是 HTTPS | 網址列不是 `https://` 開頭就會被擋 |

## 已知限制

- **Tapo backchannel 是單通道**：真人麥克風、廣播器、播歌會互相搶通道。同時用會有雜音或互相蓋掉，這是相機端限制，改不了。
- **需要 Chrome 63+ 或 Safari 11.1+**
- **不能在 Chromecast 上用**（Cast 載入不了自訂卡片）

## 附錄：這個補丁到底改了什麼

### `video-rtc.js`

| 改動 | 原因 |
|---|---|
| 新增 `setPCMACodecPreference(transceiver)` | 瀏覽器預設挑 Opus，但 Tapo backchannel 只吃 **PCMA/8000**。不指定就完全沒聲音 —— **這是最關鍵的一段** |
| 新增 `enableMicrophone()` / `disableMicrophone()` | 取得麥克風軌、並**重建 PeerConnection**（transceiver 必須在 `createOffer()` 前就存在，無法中途加入） |
| `createOffer()` 改用預存的 `this.micTrack` | 原本每次 createOffer 都重新 getUserMedia，會重複要權限 |
| `ondisconnect()` 排除 `this.micTrack` | 否則斷線時麥克風軌被 stop，下次要用重新授權 |
| 新增 `autoMuted` / `unmuteAutoplay()` | 修 autoplay 政策導致相機麥克風聽不到的問題。`play()` 只在 `NotAllowedError` 才靜音 |

### `webrtc-camera.js`

| 改動 | 原因 |
|---|---|
| 新增 `.microphone` / `.microphone.active` CSS | 紅色（關）/ 綠色（開） |
| 新增麥克風圖示與點擊處理 | 點擊切換麥克風開關 |
| 呼叫 `unmuteAutoplay()` | 卡片點擊即恢復被 autoplay 擋掉的聲音 |

## 如果對方用的是非 Tapo 相機

介面（麥克風按鈕、UI）可以照用，但**音訊格式要改**。

`setPCMACodecPreference()` 裡這行：

```js
const pcma = caps.codecs.filter(c => /PCMA/i.test(c.mimeType));
```

要改成對方相機 backchannel 接受的格式。常見的是：

- **G.711 μ-law / A-law** → `/PCMU/i` 或 `/PCMA/i`
- **Opus** → `/opus/i`
- **PCM 16-bit** → `/L16/i`

改完之後 `go2rtc` 那邊的 stream 協定也要跟著換成對應廠牌的私有協定 —— 不是每家都有，像 Reolink / Dahua / ONVIF 的 AudioOutput 支援狀況都跟 Tapo 不同，需要另外查證。
